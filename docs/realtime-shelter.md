# 避難所開設状況のリアルタイム化：可否調査と代替設計（#36）

静的な避難所データ（平時の指定避難所一覧）を、実災害時の「**いま実際に開いている避難所**」へ近づけられるか。データ供給源の一般開発者向けアクセス可否を調査し、現実的な代替設計を定める。

> 調査日: 2026-07（本ドキュメントは調査時点の公開情報に基づく。各提供元の最新の利用条件を必ず確認すること）

## 結論（先に）

**リアルタイム開設状況の「一般開発者が即座に叩ける公開API」は存在しない。** 公式の供給源（SOBO-WEB / SIP4D / L-Alert）はいずれも機関限定または審査・契約が前提。
→ 本アプリは #36 issue の方針どおり **「静的避難所＋開設状況は自治体公式へ誘導（＋将来の取り込み口を設計として用意）」** で代替する。

## 調査した供給源と可否

| 供給源 | 提供主体 | 避難所開設情報 | 一般開発者アクセス | 判定 |
|---|---|---|---|---|
| **SOBO-WEB**（新総合防災情報システム） | 内閣府 | あり（府省庁・自治体が共有） | **不可**。アカウントは国の府省庁・地方公共団体・指定公共機関に限定 | ✗ |
| **SIP4D**（基盤的防災情報流通ネットワーク） | 防災科研 | あり（被災自治体のSIP4D-ZIPを統合配信） | **不可（実質）**。ISUT経由で災害対応機関へ提供。公開開発者APIではない。2026年度にシステム更新予定 | ✗ |
| **L-Alert**（災害情報共有システム） | マルチメディア振興センター（総務省） | あり（避難所情報を配信） | **条件付き**。アプリ事業者も「情報伝達者」になれるが、FMMCの利用規約審査＋契約＋接続手続きが必要 | △（本番化オプション） |
| **自治体個別の開設状況** | 各区市町村 | 一部あり（災害時に自サイト/防災ポータルで公開） | まちまち。標準化APIなし。オープンデータ化は一部のみ | △（半自動・限定的） |

- 内閣府 新総合防災情報システム（SOBO-WEB） https://www.bousai.go.jp/taisaku/soboweb/index.html

## 代替設計（採用）

即時公開APIが無い前提で、**平時に価値を出しつつ、災害時は公式へ確実に橋渡しする**設計にする。

1. **平時（現状）**: 静的な指定避難所・避難場所データで「行ける順」を提示（本アプリの中核。開設状況に依存しない価値）。
2. **災害時の橋渡し（必須・低コスト）**: 推奨避難所ごとに、その自治体の「避難所開設状況」公式ページへのディープリンク／導線を用意し、「**開設状況は必ず自治体の公式情報で確認**」を明示（既存の免責と整合）。開設の有無という命に関わる情報を、非公式に推測で表示しない。
3. **将来の取り込み口（設計のみ）**: 自治体がオープンデータ/APIで開設状況を出す場合に備え、`opened: boolean` / `openedAt` 等の任意フィールドを避難所スキーマに後付けできるようにし、取り込みバッチ（`scripts/`）で `evacuation.geojson` にマージできる拡張点を確保する。
4. **本番運用オプション**: 事業化・本番展開時は **L-Alert 情報伝達者登録**（FMMC審査・契約）を検討。これにより避難情報・避難所情報を正規に受信できる。ハッカソン／プロトタイプ段階では対象外。

## やらないこと（誤情報リスクの回避）
- 自治体サイトの非公式スクレイピングでの「開設中」表示（更新遅延・誤判定が人命に直結するため、公式誘導に留める）。
- 開設状況の推測表示（データが無い避難所を「開いている」ように見せない）。
