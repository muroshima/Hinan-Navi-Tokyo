# 課題設定：東京で「自分が本当に行ける避難先」が分からない要配慮者

「だれでも避難ナビ TOKYO」は、**東京全域の、あらゆる要配慮者**が直面する普遍的な課題に答えるサービスです。地域・災害種別を限定しません。本ドキュメントは、その課題設定（誰の・どんな課題に答えるか）を一次情報に基づいて示します。

## 普遍的な課題：要配慮者は「行ける避難先」を平時に把握できない

既存の避難所案内の多くは、移動に制約のない人を前提にしています。しかし——

- 車椅子・高齢・乳幼児連れ・視覚/聴覚障害・オストメイト・要介護・外国語など、**配慮が必要な人**にとっては「最寄り」が「行ける」とは限りません（段差・浸水域・夜間・天候・設備の有無）。
- 災害は洪水・高潮・津波・土砂・地震・火災と多様で、**同じ避難所でも災害種別により適否が変わります**。
- 結果として当事者は「**自分（や家族）が、今いる場所から、本当に行ける避難先はどこか**」を平時に把握すること自体が大きな壁になっています。

この課題は東京のどの地域・どの災害でも生じます。本サービスは特定地区に絞らず、**東京全域 × 複数災害 × あらゆる配慮属性**を対象にします。

## 最も切実な代表ケース：江戸川区（江東5区）の大規模水害

汎用設計のうえで、**最も切実な検証シナリオ**として江戸川区の水害を重視しています（対象を限定するものではありません）。

- 江戸川区は川と海に囲まれ **陸域の約7割がゼロメートル地帯**。江東5区（江戸川・江東・墨田・葛飾・足立）では **2週間以上水が引かないエリアに約100万人が居住**。
- 区内に **要配慮者 約26万人**、**避難行動要支援者 約5,800人**。国（内閣府）の **個別避難計画作成モデル事業** の対象区。
- 「誰が・どこへ・どう逃げるか」の具体化が全国的に難航しており、当事者支援の価値が最も高い地域の一つ。

## 本サービスが答えること（東京全域で）

| 要配慮者が直面する壁 | 本サービスの機能 |
|---|---|
| 想定災害の把握が難しい | 洪水/高潮/津波/土砂のハザード（国交省）を地図に重ねて可視化 |
| その災害で「使える」避難先が分からない | 避難場所の**災害種別フラグ**で、想定災害に対応した避難先を優先 |
| 自分が行けるか分からない | 車椅子・高齢・乳幼児・視覚/聴覚・オストメイト等の属性で**バリアフリー適合を再ランキング** |
| 近いが危険・行きにくい避難先を選ぶ | **「より近いのに見送った理由」**（浸水域・段差等）を提示し当事者の判断を支援 |
| 何を・いつすればいいか分からない | 属性×災害×推奨先から**マイ・タイムライン**（内閣府の警戒レベル準拠）を生成 |
| 避難後の生活が不安 | 給水拠点・公衆Wi-Fi、（水害時は）建物高さによる**垂直避難先**を地図に重ね |
| 日本語が不自由 | やさしい日本語・英語・中国語、音声入力・読み上げに対応 |

## データの掛け合わせで生まれる「行ける順」（データ活用の核）

本サービスの価値は、**どの単独データセットにも存在しない「その人が行ける順」を、複数のオープンデータを掛け合わせて初めて生成する**点にあります。「行ける順」は生データのどこにも載っておらず、**当事者属性 × 地理 × 災害種別で結合したときにだけ立ち上がる情報**です。

### 単独データが「答えられること」と「答えられないこと」

| オープンデータ（単独） | 単独で分かること | 単独では答えられないこと |
|---|---|---|
| 避難所・避難場所一覧 | 施設の位置・名称 | その人が**行けるか**、この災害で**使えるか** |
| 避難場所の災害種別フラグ | 災害種別ごとの適否（洪水/高潮/津波/土砂/地震/大規模火事/内水氾濫/火山） | 施設まで**バリアフリーに到達できるか** |
| 車椅子対応トイレ設備情報 | 設備の有無・場所 | それが**避難先の近傍か**、**この人に必要か** |
| ハザードマップ（国交省） | 洪水・高潮・津波・土砂の危険エリア | どの避難先が**危険で、どこが代替になるか** |
| 国勢調査 小地域 高齢化率 | 地域の高齢化度合い | 個々の避難先の**優先順位** |
| PLATEAU 建物高さ | 建物の高さ（m・`measuredHeight`） | **水害時の垂直避難先**としての適否 |

どれも「地図に載せる」だけなら単独データで足りますが、**「車椅子の母と、雨の日に、洪水を想定して、いま行ける避難先はどこか」には、単独データは一つも答えられません。**

### 掛け合わせで初めて出る答え（実装に忠実な説明）

「行ける順」スコアは、以下を**同一の避難先について地理・災害・属性で結合し、加減点の総和**として算出します（`lib/ranking.ts`。score = Σ 要因）。

- **基準点** … 全施設に +100
- **距離ペナルティ**（現在地からの**直線距離**） … 遠いほど減点（夜間は近さの重みを上乗せ、荒天時はバリアフリーを要する人に限り上乗せ）
- **災害種別の適否**（避難場所の**災害種別フラグ** × 想定災害） … 対応 +25 / 非対応 −60
- **バリアフリー適合**（施設のバリアフリー属性 ＋ 近傍の車椅子対応トイレ設備 × 当事者属性） … 1階/EV・スロープ・車椅子トイレ・点字ブロック・搬送しやすさ 等を ± 加点
- **状況補正**（屋内=指定避難所か × 夜間/荒天/介助者なし 等） … 屋内滞在・夜間の近さ・雨天の屋内を ± 加点

> ⚠️ 上記が**スコアに入る要因**です。以下は**スコアには入れず、地図に重ねて意思決定を支援する文脈・レイヤ**として提示します（過大評価を避けるための線引き）:
> **ハザードタイル**（国交省・洪水/高潮/津波/土砂の危険域を目視確認）、**高齢化率**（町丁目粒度・地域文脈）、**PLATEAU 建物高さ**（水害時の垂直避難先の目安）、**給水/Wi-Fi、立ち寄り可能なバリアフリー施設（だれでも東京。避難所とは別の経路上の休憩先）**（避難後・経路上の生活継続）、**OSRM 実徒歩距離・所要**（上位候補について直線距離とは別に表示）。
>
> ※ 上の「バリアフリー適合」（スコア要因）は**避難所自身のバリアフリー属性＋近傍トイレ設備**の評価で、この重ねレイヤの「バリアフリー施設（だれでも東京）」＝経路上の休憩先とは別物です。

**具体例**: 「車椅子の母と、洪水を想定」の場合——
- *避難所データ単独*なら「最寄り」は直線300mのA小学校。
- しかしA小は**災害種別フラグで洪水に非対応（−60）**、さらに**バリアフリー情報で1階/EV情報なし（−25）**。
- 一方600m先のB施設は**洪水対応（+25）・1階受入/スロープ/車椅子トイレ有（+15/+10/+10）**。
- 結果、距離ペナルティの差（直線600m vs 300m）を補正要因が上回り、**「最寄り」ではなく B が上位**に。さらに「A小学校（より近い）は洪水非対応・段差の可能性のため見送り」と**降格理由まで提示**し、地図では洪水ハザードタイルを重ねて危険域を目視確認できます。

この**順位の逆転と根拠**こそ、単独データでは決して出せず、掛け合わせでのみ生まれる「新たな価値」です。

## 対象範囲と正直な限界
- 🟢 **東京全域対応**: 避難所/避難場所（63市区町村）・トイレ設備・給水拠点・公衆Wi-Fi・ハザード・3D地形・マイ・タイムライン・多言語
- 🟡 **23区中心（データ元の制約）**: PLATEAU建物3D（23区のみ）・都営バス停（都営バス＝23区中心）。多摩・島嶼は今後の拡張
- 福祉避難所（二次避難所）の座標付き網羅データは東京都に存在せず未統合（Issue #4）。高齢化率は**町丁目（小地域）粒度**（国勢調査小地域×避難所の BigQuery GIS 空間結合。島嶼等の未マッチは市区町村fallback）

## デモシナリオ
1. 「雨の日、車椅子の母と避難したい。介助は私がします」→ 屋内・バリアフリー・近距離を優先、天候を加味
2. 「夜に、目の不自由な父と逃げる」→ 点字ブロック・屋内・近距離・夜間の安全を加味
3. 「ベビーカーと0歳の子ども連れ」→ 段差の少ない屋内＋近傍のおむつ替え台
4. 「江戸川区で水害が心配。車椅子の母と避難したい」→ 洪水対応かつバリアフリーな避難先を優先、洪水ハザード自動表示（最も切実な代表ケース）
5. どの地域・どの災害でも、近いが危険な避難先は「行けない理由」付きで降格し、より安全な避難先を推奨

## 審査軸との対応
- **アイデア力 / ソーシャルインパクト**: 「最寄り≠行ける」という要配慮者の**普遍的課題**に、東京全域・命に直結する形で答える。最も切実な例として江東5区100万人・避難行動要支援者5,800人の大規模水害を実証
- **オープンデータ活用**: 避難所×トイレ設備×ハザード×高齢化率×給水/Wi-Fi×建物高さ×バス停を掛け合わせ「単独データでは出せない"行ける順"」を提示
- **サービスデザイン**: 当事者がことばで相談でき、根拠（なぜ1位か・行けない理由）とマイ・タイムラインまで返す。多言語・音声で言語や視覚の壁も下げる
